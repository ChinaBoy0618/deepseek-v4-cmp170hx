## F1 客户端兜底（立即，0-2 天，无服务端变更）

**改 dsf agent harness 的响应处理循环：**

1. **伪标签兜底解析**：响应无 `tool_calls` 且 content 命中
   `<bash>…</bash>` / `<Bash command>…</Bash>` / `<bash_command>…</bash_command>` /
   裸命令形态（`^\s*\w+ .*$` 且以已知命令开头）→ 正则提取命令体 → 合成
   `Bash(command=…)` 调用执行；执行前在 tool result 里附注
   `[recovered from pseudo-tag]` 留痕。
2. **重试一轮**：兜底解析失败时，向模型回发
   "上轮输出未含工具调用，请用工具通道重发"（用户在 09:55 的"继续"人工救活证明可行，自动化它）。
3. **主动 compact**：会话 prompt_tokens > 80k 触发压缩（事故阈值证据）。
4. **长参数规避**：单调用参数 > ~2KB → 指令层禁止，改为 Write 首段 + Edit 追加；
   规避 TYPE-B→0014 截断通路（08-20 活体事故）。

**验收**：用两案会话末轮 transcript 回放，死局形态全部恢复执行。
**回滚**：纯客户端逻辑，feature flag 关闭即回。

## F2 服务端 0019：信封存在性 tripwire（1 天，先只记录）

**改动**（`entrypoints/openai/chat_completion/protocol.py` + `scheduler.py` 各一小段）：

- 请求带 `tools` 且响应 finish 时 0 个 tool_call：
  - content 含伪标签签名（复用 0015 的 sig 表 + `<bash>`/`<Bash `/`<bash_command>`）→
    日志 `DSV4 0019 envelope-missing` + response 增设非标准字段 `dsv4_flags: ["pseudo_tag"]`
    （OpenAI 兼容客户端会忽略未知字段）；
  - 无签名但 finish=length → `dsv4_flags: ["budget_burn"]`。
- 不改变任何生成行为（第一周纯测量，拿概率分布决定 F3/F4 强度）。

**验收**：watchdog CSV 新增 `p119` 列（每窗口 0019 计数），跑 7 天。
**回滚**：env `DSV4_ENVELOPE_TRIPWIRE=0`。

## F3 服务端 0014 长参数豁免（2-3 天，TYPE-B 截断的直接对策）

**问题**：TYPE-B 放弃约束后 0014 只允许 64 token 就强制收尾——参数中段被硬截
（活体事故：整个 .vue 文件进 heredoc 参数，截于 `<el-d`）。

**三个选项（用 30 分钟专项测试选型：args {2k,8k,32k} × required × n=3）：**

- **(a) 参数态豁免预算**：TYPE-B 发生时若 FSM 处于参数字符串态 → 不设 64-token 上限，
  改为"继续提交直至参数闭合或 max_tokens"，完成后整体校验 JSON，坏则打 `dsv4_flags`。
- **(b) TYPE-B 拒块重试**：放弃"提交原块"，改为丢弃被拒投机块、恢复 FSM、继续正常解码
  （代价：拒收率高时解码变慢；收益：约束不丢，最干净）。
- **(c) 现状 + 显式 finish 信号**：保持 64-token 收尾，但保证 finish_reason 语义正确
  （截断时返回 `length` 而非 `stop`），客户端确定性重试。

**推荐**：先做 (c)（1 小时改动，立刻消除客户端静默烂 JSON），并行测 (b)；(a) 仅当 (b)
解码退化不可接受时启用。
**验收**：8k/32k 参数 required 调用截断率 100%→0；(b) 路径 wide_tools 200/200 + TYPE-B 后
输出全部合法。
**回滚**：0014 已有 env 开关体系，新增 `DSV4_TYPEB_POLICY={commit,retry,flag}`，默认旧值。

## F4 模板强化 v1（1 周，参照 chat_template-fix.jinja 机制移植）

**载体**：dsv4 原生模板（DSML 协议不变——词表无 Qwen token，协议不可移植），
以 `--chat-template` 挂自定义 jinja 灰度，不动模型目录。

1. **协议 CORRECT/INCORRECT 范例**进 system 段（带 tools 时）：完整参数 ✓ / 空参数 ✗ /
   截断参数 ✗ / 缺必填 ✗ —— 直接针对实测 MISSING_ARG、ARGS_BAD 类。
2. **tool_response 降噪**：`max_tool_response_chars`（默认 4k）截断 + 历史工具结果中
   `<bash>` 类文本统一包裹转义，切断模仿源。
3. **连续失败警告**：连续 ≥2 次工具错误注入 SYSTEM WARNING 文本（防死循环烧预算）。
4. **推理保留策略**：仅保留末轮 query 后的 reasoning（参照 v22.1 的 `_preserve_thinking`
   分界），历史 think 段替换为占位。

**验收（A/B）**：`depth300k.py` 与 `dual_format_agent.py` 同 seed 对拍——
ARGS_BAD+MISSING_ARG 合并率相对下降 ≥50%，其余指标不回归。
**回滚**：`--chat-template` 去掉即回原生。

## F5 工具轮关闭 thinking（1-2 周，F4 稳定后）

- 模板加 `auto_disable_thinking_with_tools` 旋钮（v22.1 同名机制）：带 tools 的轮次在
  generation prompt 预填空 `<think></think>`，砍掉协议发射前的 think 税。
- 客户端侧可先灰度：`chat_template_kwargs: {"thinking": false}` 仅工具轮。
- **验收**：finish=length 率下降；答案质量用 bench_chat_accumulate canary 把关（防
  关 think 损伤多步推理）。
